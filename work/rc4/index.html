02

Problem

#

The detection identified RC4 cipher use that was still present at meaningful scale. Rather than treating the alert as the finish line, the work continued through coordination with platform owners, remediation, and re-measurement. The environment saw a 98% reduction across an 8,000-system population.

03

Engineering decisions

#
DecisionWhyTradeoff / boundary
Treat detection as a measurement instrumentThe control objective was reducing legacy cipher use, not generating alerts.A detection can measure exposure without automatically identifying the safest remediation sequence.
Coordinate remediation with platform ownersRemediation changes can have availability consequences and need ownership outside the SIEM.Security engineering controls the finding and measurement loop, not every dependent platform.
Keep the detection after remediationRetain a regression guard so legacy behavior can be seen if it returns.Thresholds may need adjustment once the baseline becomes very small.

Implementation evidence

#
SPLRepresentative regression-guard query shape
/*
  Representative SPL shape for measuring legacy-cipher use, then keeping
  the same search as a regression guard after remediation. Sanitized
  reconstruction.

  The production event source and exact cipher observable are
  generalized on purpose. `legacy_cipher_observed` represents the
  source-specific test
  used in production; this public artifact demonstrates the measurement
  pattern without asserting whether the underlying source was Kerberos,
  TLS, or another control-plane record.
*/
index=<security_index> sourcetype=<security_sourcetype>
    `legacy_cipher_observed`
| eval affected_system = coalesce(client_host, src_nt_host, src, dest)
| bin _time span=1d
| stats dc(affected_system) as systems_still_observed
        dc(user) as accounts_involved
        count as observations
    by _time
| eval control_state = if(systems_still_observed > 0,
                          "REGRESSION_VISIBLE", "CLEAR")
| sort - _time

/*
  As a program measure, the weekly trend of
  systems_still_observed is the
  number that moves only when a fix lands. As a guard after remediation,
  alert on any day where the count rises above the documented exception
  population.
*/
Sanitized reconstruction

The exact production event source and cipher observable are intentionally generalized. The public artifact demonstrates the measurement loop without claiming a source-specific implementation.

Regression cases

  • Known legacy-cipher observations appear in the measurable population.
  • A remediated population falls while the measurement logic remains unchanged.
  • A later recurrence becomes visible as regression instead of requiring a new search.
  • Rollout monitoring includes service and dependency failures so remediation cannot be scored on security improvement alone.

05

Validation

#

The strongest validation was outcome-based: re-run the same measurement after remediation and compare the remaining RC4 population to the original baseline. Exact production event sources and thresholds are intentionally generalized here.

06

Failure modes I care about

#
  • A platform is remediated in a way that breaks a legacy dependency.
  • The observable changes after an upgrade and the detection silently stops matching.
  • A small remaining population is accepted without a documented exception path.
  • The detection is retired after success, so regression becomes invisible.
07

What I would improve next

#

Formalize the accepted-exception path and attach expiry/owner metadata so the residual population cannot quietly become permanent.

08

Questions I get asked

#
Why is this detection engineering and not vulnerability management?

The work began with a security observable in telemetry, converted it into a measurable population, and kept the same detection logic as the feedback mechanism through remediation.

What would you watch during rollout?

Impacted services, dependency failures, exception populations, and the remaining RC4 count. The goal is security improvement without availability damage.

Would you automatically block RC4?

Not from the SIEM. The safer pattern is detect, quantify, coordinate the platform change, and verify. Enforcement belongs in the control plane that owns the affected platform.

Why keep the rule once the metric is near zero?

Because the detection becomes a regression guard. A successful remediation is more durable when the original measurement remains available.
